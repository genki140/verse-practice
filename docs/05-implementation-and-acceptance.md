# 実装順序と受け入れ条件

この文書は次回の実装依頼で使う。今回の仕様作成では実装/テスト実行/公開はしていない。

## 実装ステップ

1. 独立したVite/React/TypeScriptアプリを初期化。Nodeの対応LTSを選定し、package.json engines、.node-version、lockfileに固定。MUIテーマ、hash routing、カタログ型/検証を作る。READMEに環境とコマンドを追記。Knocktellのコードをコピーしない。
2. seed12問を取り込み、抽選/選択肢シャッフル/採点/達成率を純粋関数として作る。カタログ検証をCIに接続。
3. IndexedDB schema、回答の原子保存、再開、競合、失敗時処理を作る。バックアップの検証/置換/取消を作る。
4. ホーム→クイズ→解説→結果の一連を完成し、履歴・設定・少問数・空状態を追加。日本語表示とアクセシビリティを確認。
5. PWA生成、サブパス、全資産precache、更新prompt、インストール案内を実装。previewでオフラインと新旧ビルドを検証。
6. 意味のある単体/結合/E2EとCIを作る。全必須検証を実施し、`docs/verification.md` に条件/版/観察結果/制約を記録。
7. 06の手順で公開準備。公開権限が与えられた実装依頼でのみGitHubのリポジトリ作成・push・Pages有効化・配信確認を実施。最終URLとスマホで開く手順を報告。

推奨開発コマンド契約（実装時に用意）: `npm ci`, `npm run dev`, `npm run content:validate`, `npm run typecheck`, `npm run lint`, `npm run test`（一回実行）, `npm run build`, `npm run preview`, `npm run test:e2e`。`npm run check` はcontent/type/lint/unit/buildをまとめる。CIではcheckとE2Eを通す。開発の実行環境は独立プロジェクト用に整備し、Knocktellのコンテナへ依存しない。

## リリース完了基準

check/E2E成功に加え、PWAはdev serverではなくproduction buildをHTTPSまたはlocalhostで検証。オフラインテストはすでに開いたページの通信切断だけで済ませず、ページを閉じて再起動する。旧版→新版は異なるbuildを同じorigin/scopeで配信する。

実機が利用できない場合はA19を未実施と明示し、PWA実機確認済みとは報告しない。可能なローカル検証・成果物作成までは完了させ、ユーザーが試す具体的な手順を残す。公開まで許可された依頼では、URLで起動・サブパス・manifest/SW・スマホ導線を確認し、公開成功の証拠を残す。

パフォーマンスの目標は初期配信合計2MiB gzip以下（画像を除外せず計上）、オフラインの回答表示に不自然な待ち時間なし。低速環境で初回読み込み中の状態表示。広告/解析/不要APIがないことをnetwork panelで確認する。数値達成のために正確な保存やアクセシビリティを削らない。

## 検証記録の形式

日付、commit/アプリ版/contentVersion、環境（OS/ブラウザ/表示幅）、テストコマンドの成否、A01〜A20の観察、未実施/制約、公開URL（ある場合）。個人履歴やバックアップをGitへ含めない。スクリーンショットは必要な一時証跡だけとし、文章で結果を残す。
